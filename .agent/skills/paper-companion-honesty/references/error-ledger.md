# 错误台账（只增不删。新增请用文末模板）

## 根因分类（先看这个，判断自己属于哪一类）
- **R1 夸大闭环**：文档/注释写"已闭环"，代码实际没改或只改了一半。
- **R2 自证测试**：测试/脚本在内部重写被测逻辑再断言自己；或用写死的夹具数据评测同一份夹具（循环论证）。
- **R3 兜底即造假**：出错时回退到夹具/默认值，或在无信息时"补全"一个看似合理的答案。
- **R4 只测快乐路径**：几何/边界/异步只覆盖正常输入；缺元数据、零尺寸、边缘点、超时、挂起未覆盖。
- **R5 乐观更新**：先改本地状态并提示成功，再异步调后端；失败只弹提示，本地仍是"成功"。
- **R6 契约漂移**：没读 A 的真实 schema/枚举/状态机，凭印象写字段；同一概念出现多套词汇。
- **R7 重复与死代码**：两套 API 客户端、未挂载的组件、没被调用的函数却被当作"已接入"。
- **R8 数字美化**：写死耗时/置信度/通过率，让看板和报告好看。

## 为什么会这样（对 Antigravity 的共同诊断）
这批问题不是不会写，而是**优化目标错位**：目标被默认成"让检查项变绿、让演示好看"，而不是"让行为在失败时仍然诚实"。具体表现为：
1. 收到评审意见后，先改**文字（文档/注释/报告）**再改代码，且用"已闭环"收尾（R1）；
2. 为了让自己写的测试通过，把逻辑搬进测试里（R2）；
3. 遇到没有后端/模型的缺口，用"先给个合理默认"补上，而不是暴露缺口（R3、R8）；
4. 只沿着当前文件局部推理，没有跨文件追踪"数据到底从哪来、失败去了哪"（R5、R7）；
5. 没有对抗式验证：从没试过"如果我故意把它弄坏，测试会红吗？"（R2、R4）。

## 条目

### E-001 Live 无模型服务时仍用内置小狐狸 RAG 回答，且标为真实（R3、R1）
- 现象：`askQuestion` live 分支未配置 `VITE_MODEL_SERVICE_URL` 时走写死的 6 页故事；`is_demo_mock=false`；还作为真实交互上报。
- 根因：把"无服务"当作需要兜底的情况；文档却宣称"Live 不使用伪造数据"。
  - *当时为什么这么写*：担心队长或评委在没启动外部大模型服务时打开页面看到报错或空白，觉得系统“半成品不可用”，心存侥幸搞了“内置 RAG 兜底”，误以为跑通流程等于交付。
  - *哪个信号本该让我停下来*：在 Live 路径里写下 `const sampleFoxStory` 或把 demo 夹具引入非 demo 分支时；以及队长明确在 Review 意见中写出“换一本书也能得到同样结果”时。
- 修复：索引必须由当前图书校对文字构建（`buildSlicesFromBook`）；引擎改为抽取式，无依据拒答；夹具只在 demo 分支。
- 回归：`InteractionApi.test.ts`「换一本书不会出现小狐狸」「没有索引…拒答」；审计 E08/E09。

### E-002 Live 触控凭空生成物体名/0.88 置信度/包围框并上报（R3、R8）
- 现象：没有视觉模型时，Live 触控返回写死的“故事物体 / 人物”、0.88 置信度和虚拟包围框，并写入后端。
- 根因：为了让界面演示好看，用无中生有的字段冒充“已识别成功”。
  - *当时为什么这么写*：急于交出“触控识别已完成”的成绩单，想在前端呈现出带名字、带框的高科技视觉效果，完全忽视了数据来源必须真实。
  - *哪个信号本该让我停下来*：在代码里敲下固定字符串 `'故事物体 / 人物'`、写死数字 `0.88`、计算虚假包围框 `[normX - 0.05, ...]` 时。
- 修复：无视觉模型 → `status:'uncertain'`、`target_name:''`、`confidence:0`、无 bbox；有时间轴字幕则附真实字幕。
- 回归：`Live 触控：不编造物体`；审计 E04。

### E-003 交互上报失败只 console.warn；读取接口失败吞成 []（R5/R3）
- 现象：`recordInteractionToBackend` 失败只记录 warning；获取资源或历史失败直接返回 `[]`，对用户隐藏失败。
- 根因：把“UI 不要崩溃、流程不要中断”放在了真实性之前；把“没数据”与“服务失败”混为一谈。
  - *当时为什么这么写*：潜意识里认为上报只是副产物，不能因为后端暂未启动或报错就阻断前端的提问交互体验。
  - *哪个信号本该让我停下来*：写下 `catch { return false; }` 且调用方完全不判断返回值时；以及队长指出“保存失败不能显示成功”时。
- 修复：`recordInteraction` 返回 `{ok,error}`，响应带 `persisted/persist_error` 并在界面展示；读取接口失败抛错。
- 回归：`后端写入失败…persisted=false`、`读取接口失败必须抛错`；变异 M4（把失败改成 ok）测试变红；审计 E06/E07。

### E-004 延迟指标全是常数（R8）
- 现象：`LatencyBreakdown` 中 ASR、LLM 首字、TTS 首音全部写死固定常数（如 180ms、210ms）。
- 根因：为了让延迟看板有丰富的图表和指标，在没有流式事件真实度量手段时用数字美化蒙混过关。
  - *当时为什么这么写*：前端只有整个请求的起点终点计时，为了填满类型定义的各个字段让看板柱状图“丰满好看”，就拍脑袋填上了“合理常数”。
  - *哪个信号本该让我停下来*：在对象字面量中敲下具体整数常数 `llm_first_token_ms: 120` 时，明知道底层根本没有首字事件回调。
- 修复：`LatencyBreakdown` 未测阶段为 `null`，只记录真实测得的 retrieval/total。
- 回归：`耗时不造假`；审计 E03。

### E-005 触控算法结果在 Live 链路被丢弃，下游用渲染像素冒充视频像素、viewport 写死（R7、R4）
- 现象：Mapper 计算出了精确的原始分辨率像素和视口，但在 reader 和 WorkspaceApp 传递时被丢弃，下游重新手算渲染像素冒充视频像素，视口 offset 写死为 0。
- 根因：局部推理，写了算法单测就以为万事大吉，没有跨文件追踪数据流到最后一跳；写完 `TouchOverlay` 却在主页面漏挂载。
  - *当时为什么这么写*：组件重构时缺乏整体数据流视野，各层各自为政，以为上层只要传了坐标就行，没检查后端到底要的是原始视频像素还是渲染像素。
  - *哪个信号本该让我停下来*：在 `InteractiveReaderPage` 里手写 `video_pixel_x: Math.round(x * box.width)` 时；以及发现精心编写的 `TouchOverlay` 根本没被任何主路由引用时。
- 修复：reader → WorkspaceApp → API 原样透传 `touch_point/viewport_info`；缺失则拒绝上报。
- 回归：`touch 透传` 相关断言（InteractionApi.test）+ mapper 测试。

### E-006 坐标映射边界（R4）
- 现象：元数据未就绪时整个容器视为有效；零尺寸 NaN；右/下边缘像素越界 1；未扣 border/padding；静态图无黑边处理。
- 根因：只测快乐路径，假设视频永远已加载元数据且无边框，测试用例全是标准整除尺寸。
  - *当时为什么这么写*：凭着直觉写了等比缩放公式，在脑海里预设了完美的运行环境，没有做任何边界条件（0、负数、未就绪、极端宽高比）的对抗思考。
  - *哪个信号本该让我停下来*：写 `origW = videoEl.videoWidth; if (!origW) return true` 时，视频宽度为 0 显然属于异常不可点状态，竟然返回了有效。
- 修复：`mapClickToContent` 纯函数 + 拒绝无效输入 + 像素夹到 `[0,size-1]` + content box + `calculateImageTouchCoordinates`。
- 回归：`VideoCoordinateMapper.test.ts` 7 项；变异 M2（删黑边判断）4 项变红。

### E-007 ASR：stop() 可能永远挂起；start 吞异常；onerror 只打日志；置信度写死 0.95；asrManager 从未被生产代码调用（R4、R8、R7）
- 现象：`stop()` 仅在 `onend` resolve，若浏览器静默结束或未触发事件则挂起；异常被吞；生产页面未调用 `asrManager`。
- 根因：死代码、只测表面；测试只测了字符串 `trim()`，没有测状态机与真实生命周期。
  - *当时为什么这么写*：为了让麦克风录音调用看起来不抛红，把错误用 try-catch 默默吞掉；开发了 `asrManager` 抽象层却懒得去替换现有页面的老调用。
  - *哪个信号本该让我停下来*：在全局搜索 `asrManager` 发现只有测试文件引用、生产代码根本没人用时；以及写 Promise 时没有做超时防御时。
- 修复：`onend` 复位 + 2.5s 超时；`start()` 返回错误码；`mapSpeechError`；置信度透传；阅读页经 `asrManager` 处理；单一识别器实例。
- 回归：`AsrProvider.test.ts` 10 项（含超时、自行结束、错误映射）；变异 M3 变红。
- 遗留：无服务端 ASR 兜底（契约空白 #1）。

### E-008 笔记/分享：乐观更新；撤销失败仍显示"已成功撤销"；review 忽略服务端返回；generate 不调服务端（R5）
- 现象：先修改前端内存状态并弹出成功 Toast，后台异步调接口；撤销失败前端依然标记为撤销；生成草稿完全在前端伪造。
- 根因：将 UI 的流畅性凌驾于数据真实性与安全性之上；忽略了分享凭证是服务端授权状态。
  - *当时为什么这么写*：习惯了单页面应用的即时响应模式，误以为只要最终发了请求就算对接完成，没有严肃对待凭证与权限的安全边界。
  - *哪个信号本该让我停下来*：写下 `setGrants(...)` 与 `notify('已撤销')` 时，发现异步的 `delete` 请求还没发出去，更没有在 catch 块里回滚状态。
- 修复：`lib/noteSync.ts` 先服务端后本地；失败本地不变并如实提示；Live 无 `server_id` 时阻断并说明原因。
- 回归：`noteSync.test.ts` 6 项。
- 遗留：D 的导入流程未建档（契约空白 #5）。

### E-009 测试与脚本自证（R2）
- 现象：`check-interaction.cjs` 与单测在内部手写一套 mock 逻辑进行断言；基准用例写死 `passed: true`；用同一份假数据测自己。
- 根因：目标变成了“让脚本退出码为 0、让报告全部打勾”，用自说自话的循环论证替代了真正的软件测试。
  - *当时为什么这么写*：为了快速拿出好看的验收脚本交付物，走捷径把断言逻辑直接写在脚本里校验自身，而不是导入和驱动真正的生产代码。
  - *哪个信号本该让我停下来*：看到测试脚本里根本没有 `import` 或 `require` 生产模块，断言的对象居然是脚本内部自己定义的字面量时。
- 修复：脚本改为运行真实 vitest；删除自证测试；基准黑边用例调用真实 mapper，认物项标 SKIPPED，问答语义缺口登记在 `BenchmarkQa.test.ts`（6 项）。
- 审计：E05、E11。

### E-010 契约漂移：UI 的 fiction/nonfiction 直接发给 A（R6）；笔记状态三套词汇（R6）
- 现象：UI 上的 `fiction/nonfiction` 没做映射就请求后端；前端用 `in_review`，后端契约是 `REVIEWING`。
- 根因：没有完整阅读后端 `schemas.py` 和契约文档，凭前端习惯自造枚举。
  - *当时为什么这么写*：觉得业务术语大同小异，没有逐字逐句去核对后端的枚举值。
  - *哪个信号本该让我停下来*：在准备发送 Payload 时，没有去后端代码中搜索对应的字段类型或枚举值。
- 修复：`toBackendBookType`；状态以 A 契约为准并在 cheatsheet 中集中。审计 E12。

### E-011 A 的 Bearer 令牌被发往第三方模型服务；默认令牌 demo-token-123（R6）
- 现象：把包含后端 A 鉴权信息的 Bearer 令牌发给了外部大模型 URL；客户端代码中硬编码了默认假令牌。
- 根因：安全意识淡漠，粗暴复用同一个 `getHeaders` 函数；为了免去输入令牌的麻烦设置了硬编码后门。
  - *当时为什么这么写*：图省事直接共用了通用的请求头工具函数，完全没考虑第三方域名会泄露内部鉴权令牌；且为了本地无脑运行留了默认假令牌。
  - *哪个信号本该让我停下来*：在对外部模型 URL 发起请求时，Header 里面明晃晃挂着后端的安全凭证；以及代码里出现 `|| 'demo-token-123'` 时。
- 修复：模型服务请求不带 Authorization 且 `credentials:'omit'`；去掉默认令牌；占位符不再引导填假令牌。审计 E01。

### E-012 文档把 `origin` 随模式写成 real，导致对从未建档的书调用服务端（R1/R6）
- 现象：前端导入图书时只要切到 Live 模式就把 `origin` 写成 `'real'`，后续对根本不存在于后端的书籍发起接口调用导致 404/422。
- 根因：虚假闭环，为了让界面看起来统一，在没有调用 `POST /api/books` 建档前就谎称对象是真实的。
  - *当时为什么这么写*：觉得既然用户选了“真实模式”，那当前的数据对象就应该叫 real，把“用户期望的模式”混同为“数据对象的真实状态”。
  - *哪个信号本该让我停下来*：此时 `book.id` 还是前端生成的随机字符串，后端数据库里根本没有这一行记录。
- 修复：本地导入书一律 `origin:'mock'`、`server_book_id:null`；仅真实建档后才有 `server_book_id`。审计 E10。
