## 4. 怎么再次备份

先暂停上传、编辑和生成，保持 MongoDB 运行。备份脚本必须使用有项目依赖的 Python：

```powershell
& .\backend\.venv\Scripts\python.exe .\scripts\backup-desktop.py --destination 'D:\Documents\PaperCompanionBackups'
```

校验（默认仅校验文件、解包源码与 SQLite 隔离恢复，不写 MongoDB）：

```powershell
& .\backend\.venv\Scripts\python.exe .\scripts\verify-desktop-backup.py 'D:\Documents\PaperCompanionBackups\具体时间目录'
```

额外加 `--mongo-restore-test` 会在原 MongoDB 实例建立随机临时库，恢复集合和索引核对后移除该临时库；不会覆盖项目正式库，但需足够磁盘空间。
本机本轮 `.venv` Python 写 D 盘出现权限拒绝，实际备份使用同版本 `C:\Python314\python.exe` 加载现有虚拟环境包执行，没有重新安装依赖或修改系统配置。

SQLite 使用官方备份 API，MongoDB 导出逐集合前后核对内容；不是应用整体原子快照。备份期间应保持无人写入。
失败目录会标记 `BACKUP-INCOMPLETE`，不得作为完整恢复点。

## 5. 恢复原则（先恢复副本，不能直接覆盖）

1. 阅读私有说明并校验所有文件哈希。
2. 在全新目录解压 `desktop-source.zip`，不要覆盖现在的项目；按锁文件/requirements 重建依赖。
3. 业务库先恢复到新的 SQLite 路径，运行完整性检查；媒体保持原目录层次。
4. MongoDB BSON 先恢复到新库名，按 metadata 恢复索引并核对用户记录、密码登录和会话有效期。导出格式是本脚本逻辑格式，不可把整个目录盲目交给 mongorestore。
5. 使用 `DATABASE_PATH`、`DATA_ROOT`、`MONGODB_DATABASE` 指向隔离副本，测试通过后再安排正式切换。
6. Git bundle 用于恢复历史；工作目录压缩包是最终文件状态。只有确实需要还原暂存区别时才由熟悉 Git 的人处理索引/补丁，避免在已包含最终修改的源码上重复打补丁。
7. 跨电脑重新配置模型密钥和网络地址；不要复制旧电脑的本地访问地址当作共享入口。

本轮提供备份与安全校验工具，**不提供默认覆盖正式数据的一键恢复按钮**。
