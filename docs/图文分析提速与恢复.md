# 图文分析提速与恢复

新建图文分析默认开启快速模式、同时处理2页；故事工坊可关闭快速模式，并在1至3页并发间选择。确认清单包含本次模式、并发页数和收费页码。问答、认物、文字定位的思考设置不受影响。

每页仍单独请求、通过结构校验后保存，结果按原页码排序。摘要要求简洁，只描述重要可见事实，保留原图、人工校对文字、关键对白和无字情节。图片维持最长边1600像素，不进一步降低清晰度。没有实测云端提速倍数，快速模式的内容质量仍需对照原图核查。

数据库增加 `vision_pages`，记录未发送、发送中、已保存及结果不明。一次失败会停止调度后续页，已发送的其他页继续等待并保存结果。每页记录耗时、准备耗时、错误类别、HTTP状态、供应商请求ID及返回的Token统计；不保存密钥或供应商错误原文。Token数和任务数不等于账单金额。

“继续未发送书页”先显示确认清单，只恢复最早一个有未发送页的失败批次；沿用该批次保存的模式、模型、来源指纹和并发参数。旧版批次没有模式/并发参数时，沿用原默认思考、串行设置。成功页直接复用；超时、网络中断、接口错误、输出格式错误等已尝试请求均保守标为结果不明，不自动重发。重启遗留的发送中状态也视为结果不明。来源或模型变更时禁止恢复。

旧版程序逐页串行并立即落库，因此失败批次的首个未保存页视为结果不明，后续页视为未发送；已有成功结果保持不变。这项推断只适用于旧串行版本，新版优先使用持久化页级记录；新版缺失记录时保守阻止重发。

接口：

- `POST /api/runs/{id}/workflow/vision`：`page_nos`、`confirm_paid`、可选 `fast_mode`（默认true）、`concurrency`（默认2，范围1至3）。同一批次重复提交返回原任务，不改变参数或重复调用。
- `POST /api/runs/{id}/workflow/vision/resume`：`confirm_paid:true`，仅恢复确认未发送页。
- `POST /api/runs/{id}/workflow/vision/reuse`：免费复用同一本书、相同来源指纹、模型及页面图片的已保存分析，补齐结果不明页；不调用供应商。
- `POST /api/runs/{id}/workflow/vision/retry`：仅在明确确认可能重复计费后，重发所选结果不明页；已保存页不能重发。
- `GET /api/runs/{id}/workflow`：新增 `vision_progress`、`vision_resume_available`、`reusable_vision_page_nos`；保持原结果、分镜与任务结构。

离线测试覆盖：有界并发、乱序返回、成功页立即保存、失败时在途成功页保存、停止新增请求、未发送页恢复、结果不明不重发、旧串行任务恢复、重启恢复、来源变更、授权及错误脱敏。真实供应商限流、耗时和识别质量需在用户实际提交后进一步核验。
