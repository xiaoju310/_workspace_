# 纸书智伴：可实施的产品与技术设计文档

**版本**：v0.3（扩展设计讨论稿）　**日期**：2026-11-03　**状态**：方案设计，尚未开发或实测
**依据**：用户提供的《纸书智伴-赛题要求提炼.md》、浏览器打开的 2026 年第 6 题「纸书智伴」赛题详情页，以及下文所列技术官方文档。官网简介明确提出“可拍照、可生成、可交互”，并提及决赛现场新绘本的限时改造。
**标记**：`要求`＝赛题材料约束；`方案`＝本队建议做法；`待确认`＝需在技术说明会或拿到比赛环境后核定。本稿不是官方规则，也不把目标指标写成既有成绩。

## 0. 一页结论

做一个适配电脑和平板的智能阅读平台：用户导入图书后，系统先判断图书类型，再调用对应的分析流程，生成结构化内容和读书笔记；对适合视频化的内容生成有旁白的视频，对不适合整书视频的内容生成章节讲解/知识点视频。主人审核笔记后，才可以按权限分享给其他用户。原赛题要求的绘本互动视频、语音提问和触控认物仍是两周竞赛版的 P0 主链路。

**推荐栈**：React + TypeScript + Vite 前端；Python + FastAPI 后端；SQLite + 本地文件做开发期存储；独立 worker 负责生成任务；PaddleOCR 做文字识别；Qwen3-VL-4B-Instruct 作为视觉理解候选；FunASR 做中文语音识别；CosyVoice 做语音合成候选；真实的文生/图生视频模型通过 `VideoProvider` 接口接入；FFmpeg 负责拼接和音画同步。模型版本、许可证、可用 GPU 和是否允许第三方 API 均在环境验证后锁定。

**硬约束**：竞赛版的内容理解、互动视频、实时语音/触控、多 Agent 缺一不可；回答正确率基础门槛 ≥0.60；交互延迟具体门槛待官方定稿；关键生成结果须可定位和复现。不能拿预生成视频冒充现场生成，不能仅用图片平移/缩放冒充“文生视频”。扩展版不承诺对所有图书百分之百自动成功：系统必须允许用户确认/修改分类、人工校对分析结果，并对不支持的格式或低置信度结果明确提示。

## 1. 范围、角色与验收边界

### 1.1 两种使用模式

- **制作模式**（家长/演示员）：选择授权书、拍照或上传、确认页序和 OCR、发起生成、查看进度、人工复核儿童内容。
- **伴读模式**（读者/评委）：播放视频、语音提问、触控识别、查看简短回答与证据。开发与评测使用模拟读者，不采集真实儿童个人信息。
- **通用阅读模式**（扩展版）：导入绘本、小说、教材、科普、历史、诗歌、漫画或工具书；系统自动分类并由主人确认，生成结构化分析和读书笔记。
- **笔记分享模式**（扩展版）：笔记默认仅主人可见；主人审核后可指定用户查看或生成限时分享链接，并能随时撤销。默认不分享整本书原文、扫描页或未授权衍生内容。

### 1.2.1 通用图书类型与专用分析策略（扩展版）

系统采用“统一导入 + 类型路由 + 专用分析器”的设计，而不是给每一本书写一套固定代码。首期支持以下常见类型，其他类型进入 `other` 并提示人工确认：

| 类型 | 识别重点 | 笔记模板 | 视频化方式 |
|---|---|---|---|
| 绘本 | 页面文字、角色、场景、物体、情节 | 故事梗概、角色、情节、感受 | 逐页互动视频（竞赛 P0） |
| 小说 | 章节、人物、关系、冲突、主题 | 梗概、人物关系、主题、问题 | 章节讲解视频；不承诺整本实时生成 |
| 教材 | 标题、知识点、公式、例题、难点 | 知识点、复习提纲、错题/自测 | 知识点讲解视频 |
| 科普/历史 | 概念、事实、时间线、因果和数据 | 核心事实、时间线、概念解释 | 章节摘要或知识点视频 |
| 诗歌/漫画/工具书 | 意象、分镜、步骤、定义和注意事项 | 赏析、剧情节点、操作清单 | 按页面/章节选择视频模板 |

分类流程：用户选择或自动判断 → 输出类型、置信度和理由 → 主人确认/修改 → 选择对应 `BookAnalyzer`。低置信度不得直接进入生成任务。

### 1.2.2 读书笔记与授权分享（扩展版）

读书笔记必须是可编辑、可追溯的结构化草稿，而不是只生成一段不可修改的长文本。建议字段包括：摘要、章节/页面要点、人物或概念、主题、问题、个人感想、来源页码/章节和生成模型版本。状态为：`DRAFT → REVIEWING → PRIVATE → SHARED → REVOKED`。

分享规则：

1. 默认 `PRIVATE`，只有主人可见；
2. 只有主人能修改、审核、创建分享和撤销分享；
3. 首期支持指定用户和限时链接两种方式，公开广场属于后续 P2；
4. 分享只展示经过主人确认的笔记，不默认展示完整图书、扫描页、音频或视频原始资产；
5. 分享令牌只保存哈希，支持过期、撤销、禁止下载和访问记录；
6. 笔记中的长引用要受版权与赛事授权限制，优先使用总结和短引用并保留来源标记。

### 1.2 MVP 功能清单

| 编号 | 功能 | 完成定义 | 优先级 |
|---|---|---|---|
| F1 | 绘本导入与页序校对 | JPG/PNG 页图上传；缩略图、排序、重传；拒绝过大/损坏文件 | P0 |
| F2 | 图文理解 | OCR 文字及位置；VLM 角色、场景、物体、故事事件；人工修改后保存 | P0 |
| F3 | 故事与视频生成 | 全书大纲→逐页脚本→至少逐页真实生成视频片段→旁白/字幕→合成可播放成片；每段记录生成方式 | P0 |
| F4 | 语音问答 | 浏览器录音→ASR→当前视频时间/全片检索→依据约束的短答→TTS；显示转写、文字答复、证据 | P0 |
| F5 | 触控识别 | 点击视频可见物体→定位当前帧与点击区域→返回名称、解释、置信/不确定提示及时间证据 | P0 |
| F6 | 多 Agent 与追溯 | 各模块独立输入/输出；编排状态、失败重试、run_id、日志、模型/提示词版本 | P0 |
| F7 | 多模态历史与评测 | 保存本次音频引用、ASR、点击帧/坐标、回答；导出延迟和准确率原始记录 | P0 |
| F8 | 家长定制、小测验、角色对话 | 不影响 P0 完整闭环时再做 | P2 |

**第一轮范围**：先让 1 本授权书从导入到互动完整跑通，再覆盖 6 本与新书输入。绝不把“只支持一书”当作最终赛题完成；是否能完成全部书取决于页数、GPU 与视频模型的实际生成耗时，需在第 1 周实测并调整片段长度/并行度。

## 2. 技术栈与选型理由

| 层 | 首选 / 备选 | 为什么这样选；验证条件 |
|---|---|---|
| 前端 | React + TypeScript + Vite；浏览器 MediaRecorder、`<video>` | 一套响应式网页覆盖电脑和平板；组件分工清楚。先测比赛平板浏览器的麦克风权限、视频格式和触摸坐标。 |
| API | FastAPI + Pydantic | 用 JSON 契约连接前后端；文件上传、模型调用与评测适配都用 Python。进度先每秒轮询，不依赖 WebSocket；语音流式优化再加 WebSocket。 |
| 耗时任务 | 单独的 Python worker + SQLite 任务表；规模需要时换 Redis/RQ | 视频生成绝不能在 HTTP 请求里等待完成。首版一个 GPU worker 顺序消费，避免显存争抢；API 只返回 job_id。官方环境若允许 Redis，可替换队列实现。 |
| 数据 | SQLite（WAL）+ 受控文件目录 `data/`；后续可迁 PostgreSQL/对象存储 | 比赛 Demo 易部署；表内存元数据，图片/音频/视频保存在文件，数据库只存相对路径、哈希与引用。不要把受限素材提交到 Git。 |
| OCR | PaddleOCR 3.x PP-OCRv5 候选 | 输出文字、文字框、置信度；模型包与 CPU/GPU 兼容性先验证。 |
| VLM/故事 | Qwen3-VL-4B-Instruct 候选；统一 `VisionProvider`/`StoryProvider`，可换官方允许的服务 | 视觉理解与故事写作均输出经 Pydantic 校验的 JSON。小模型能否正确识别绘本需用样本实测，不能预设性能。 |
| 视频 | 首选经 GPU 验证可用的图生视频模型（如 HunyuanVideo-1.5 480p I2V）；同时保留 T2V 验证路径；备选合规第三方服务 | 用原书画面约束风格，以脚本提示词生成动态片段。该候选官方写明 Linux、CUDA、最低 14 GB 显存（开启 offload）；**这只是模型最低运行条件，不是整套系统的显存保证**。没有合适 GPU 或许可时立即换经批准的服务，不以静态特效充数。 |
| ASR | FunASR 离线/在线候选 | 先做“点击录音→提交音频→返回转写”，按提供的 Query 音频测中文识别；之后再做流式。 |
| TTS | CosyVoice 候选；失败时可换经批准的 TTS 服务 | 生成旁白与简短语音回答。具体版本、权重授权、资源消耗与启动时间实测决定。 |
| 合成 | FFmpeg | 统一片段编码、拼接、混音和字幕；不是生成模型。 |
| 测试与运行 | pytest、前端基础组件测试、固定输入的集成测试；Linux 优先部署 | 官方云 GPU 环境尚未公布；模型服务与 Web/API 可分进程/容器，先在可获得的机器做 smoke test。 |

**不要一开始加入** Kubernetes、向量数据库、复杂 Agent 框架、用户账号系统或模型微调。六本书规模下先用页码/时间过滤 + SQLite FTS/关键词检索 + VLM 核对；若实测召回不足再加 embedding。所有外部服务必须先核对授权、数据发送边界、费用和比赛规则。

## 3. 系统架构与链路

```text
浏览器（响应式 Web）
  拍照/上传 ─ 校对 ─ 进度 ─ 播放/录音/点击 ─ 会话历史
        │ HTTPS/本地受控连接；进度 GET 轮询
        ▼
FastAPI（鉴权/允许的本地访问、输入校验、文件访问、评测适配）
        │ 创建 job_id / run_id；读写结构化结果
        ├───────────────────────────────┐
        ▼                               ▼
SQLite：books/pages/runs/jobs/         文件：原页、OCR、脚本、
segments/interactions                   片段、成片、音频、点击帧
        ▲                               ▲
        └────────── worker ─────────────┘
                    │
       OCR Agent → VLM Agent → 故事 Agent → 视频 Agent
                                      → TTS/合成 Agent
                    │
       播放时：ASR → 检索/问答 Agent → TTS
                 点击帧 → 视觉定位 Agent → 解释
                    │
       安全复核 + 日志/指标（贯穿所有环节）
```

这里的 **Agent** 指有明确职责、输入输出、重试与日志的可替换模块，不必让多个大模型自由聊天。编排器是确定的状态机：`UPLOADED → PARSING → REVIEW_REQUIRED → GENERATING → SAFETY_REVIEW → READY`，失败进入 `FAILED` 并记录失败阶段和可重试性；人工修改后以新版本继续，不静默覆盖原结果。

**生成链路**：每页图预处理→OCR/VLM 并行→合并为 `BookGraph`→人工确认→全书故事大纲/角色风格表→逐页脚本与视频提示词→逐页真实视频片段→旁白 TTS→FFmpeg 合成→建立视频时间轴/抽帧索引→安全复核。生成完才进入可互动状态。片段失败时可展示明确标记的静态降级页，但不算该页的视频生成完成。

**互动链路**：提问时先锁定本次运行的 `book_id/run_id` 和播放时间；检索优先命中当前片段，再考虑全片；回答必须附页码/时间和证据类型（原书、脚本、生成视频帧），缺证据就说“不确定”。点击时客户端发送画面内的归一化坐标和 `currentTime`，服务端按视频原始尺寸映射、截取对应帧及周边区域，再做物体定位；不能只查询原书静态物体表，因为生成视频可能变化。

## 4. 数据结构与 API 契约（首版即可编码）

### 4.1 核心表与文件

| 表 | 必要字段 | 用途 |
|---|---|---|
| `books` | id, title, authorization_ref, created_at | 一书；来源须可追溯 |
| `pages` | id, book_id, page_no, image_path, sha256, ocr_json, vision_json, revision | 原图与人工校对内容 |
| `runs` | id, book_id, status, config_json, model_manifest_json, created_at, finished_at | 每次生成不可混用；保存版本、种子、提示词哈希 |
| `jobs` | id, run_id, stage, status, attempts, error_code, started_at, ended_at | worker 领取、失败/重试、阶段耗时 |
| `segments` | id, run_id, page_no, video_path, start_ms, end_ms, prompt_hash, generation_mode, evidence_json | 视频时间轴；区分 I2V/T2V/静态降级 |
| `interactions` | id, run_id, kind, video_ms, input_path, input_text, click_json, answer_text, evidence_json, latency_ms, created_at | 多模态历史和指标原始数据 |

扩展版在 `books` 增加 `book_type`、`type_confidence`、`classification_status`、`owner_id`；新增以下表：

| 表 | 关键字段 | 用途 |
|---|---|---|
| `book_classifications` | book_id, predicted_type, confidence, reasons_json, confirmed_type, confirmed_by | 保存自动分类和主人确认记录 |
| `chapters` | id, book_id, chapter_no, title, start_page, end_page, content_json | 支持小说、教材和科普书按章节分析 |
| `book_entities` | id, book_id, kind, name, description_json, source_ref | 保存人物、概念、物体、事件等可复用实体 |
| `reading_notes` | id, book_id, owner_id, content_json, status, version | 保存读书笔记草稿、审核版本和来源引用 |
| `note_revisions` | id, note_id, version, content_json, editor_id, created_at | 支持修改记录和回滚 |
| `note_shares` | id, note_id, owner_id, share_mode, shared_user_id, token_hash, expires_at, revoked_at | 控制指定用户/链接分享和撤销 |

`note_shares` 的 `share_mode` 首期取 `invite_only` 或 `link`；不直接保存明文分享令牌。正式多人使用前还需要用户登录、身份校验和权限中间件。

文件路径必须由后端生成并限制在 `data/` 根目录下；下载资产只通过带类型校验的受控接口，不能让前端传任意本机路径。受限原图、音频、视频、日志不得进入公开仓库。

### 4.2 最小接口

| 方法与路径 | 输入 | 输出 / 约定 |
|---|---|---|
| `POST /api/books` | 标题、授权样本标识 | `book_id` |
| `POST /api/books/{id}/pages` | multipart 图片及页码 | `page_id`、图片哈希；仅 JPG/PNG、大小限制配置化 |
| `POST /api/books/{id}/parse` | 无 | `job_id`；异步 OCR/VLM |
| `PATCH /api/books/{id}/pages/{page_id}` | 已校对文字/实体/事件、revision | 新 revision；旧版本冲突返回 409 |
| `POST /api/books/{id}/runs` | age_band、voice、model_profile | `run_id`、`job_id`；异步生成 |
| `GET /api/jobs/{id}` | 无 | stage/status/progress/error_code；前端轮询 |
| `GET /api/runs/{id}` | 无 | 结果、视频 URL、页/时间轴、复核状态 |
| `POST /api/runs/{id}/questions` | 音频文件、`video_ms` | 转写、回答、音频 URL、证据、耗时；首版非流式 |
| `POST /api/runs/{id}/touches` | `video_ms, x_norm, y_norm, rendered_box` | 目标、解释、证据、置信/无法判断、耗时 |
| `GET /api/runs/{id}/interactions` | 无 | 本次会话历史 |
| `POST /api/books/{id}/classify` | 可选类型和自动判断开关 | 类型、置信度、理由、分类任务状态 |
| `PATCH /api/books/{id}/classification` | 主人确认的类型 | 新分类和确认人；低置信度需明确确认 |
| `POST /api/books/{id}/analyze` | analysis_profile | 对应类型的结构化分析任务 |
| `POST /api/books/{id}/notes/generate` | note_template | 生成带来源引用的笔记草稿 |
| `GET /api/notes/{id}` | 无 | 笔记内容、版本、审核状态 |
| `PATCH /api/notes/{id}` | 修改后的结构化内容 | 新版本；主人操作 |
| `POST /api/notes/{id}/review` | approve/revise | 主人审核后转为 PRIVATE |
| `POST /api/notes/{id}/shares` | share_mode、用户/过期时间 | 创建待授权分享 |
| `DELETE /api/notes/{id}/shares/{share_id}` | 无 | 撤销分享 |
| `GET /api/shared-notes/{token}` | 分享令牌 | 按权限读取已审核笔记 |

**示例：提问响应**（字段示意，不冒充官方评测 schema）：

```json
{
  "transcript": "小熊刚才去了哪里？",
  "answer": "视频里小熊走进了森林。",
  "audio_url": "/api/assets/audio/abc",
  "evidence": [{"source": "video_frame", "page_no": 3, "start_ms": 18000, "end_ms": 26000}],
  "latency_ms": 2100,
  "uncertain": false
}
```

**示例：点击输入**：`{"video_ms": 21540, "x_norm": 0.42, "y_norm": 0.63, "rendered_box": {"width": 800, "height": 450}}`。`x_norm/y_norm` 以**实际视频内容区域**而不是整个播放器外框归一化；前端要扣除 `object-fit: contain` 的黑边，服务端拒绝超出 `[0,1]` 的输入。生成片段中的点击帧与页级静态实体只是候选，最终还需对当前帧核对。

**官方评测接口**：专设 `eval_adapter/`，待 schema 公布后实现输入/输出转换，不让官方字段渗透产品内部模型。未知协议、延迟阈值、隐藏测试是否有新书，全部保留为待确认项。

## 7. 测试与验收

**最先做的自动化**：上传错误文件返回 4xx；页序与 revision 冲突；worker 重启后任务可恢复/明确失败；一个 Agent 超时不会让 run 永久卡住；时间轴连续且最后一段结束时间与成片时长一致；点击黑边不识别；无证据问答不编造；同一运行可查到输入哈希、模型配置与产物。

| 赛题维度 | 测量办法 | 文档里可写的目标 |
|---|---|---|
| 回答正确率 | 用组委会提供的每本 50 条 Query 音频测试；按官方判分记录正确数/总数，错误分 ASR、检索、生成 | **要求 ≥0.60**；实际数值待测，不用自制题代替官方结果 |
| 视频内容检索 | 每条回答记录所依据页码与时间片，人工复核证据是否真的在视频中 | 官方是否要求时间戳待确认 |
| 触控识别 | 制作不同帧/位置/遮挡的标注点击集，统计 top-1、误识和拒答 | 官方类别/开放式判分待确认 |
| 延迟 | 客户端提交音频/点击时记起点，首字与首音频分别记终点；报告 P50/P95、超时率 | 基础门槛数值待确认；示例 JSON 中耗时非实测承诺 |
| 生成质量 | 盲评风格、页间连贯、文字忠实；记每页/全书生成耗时与失败率 | 至少一书全流程成功，再逐本扩展 |
| Agent/合规 | 展示逐阶段输入输出、失败重试、来源清单、安全复核、复现步骤 | 关键内容可定位、可重跑，素材使用合规 |

**演示失败不造假**：保留本地视频/截图作为故障说明并标注“历史生成”；同时展示当前新任务的真实 job/run、时间戳和日志。静态降级页、人工修改、缓存命中均在记录中可见。

## 8. 扩展路线与两周范围

- **竞赛两周版（P0）**：优先完成授权绘本导入、OCR/VLM、真实视频片段、语音问答、触控识别、运行日志和演示；分类器先实现 `picture_book` 与 `other` 两类路由。
- **通用阅读第一阶段（P1）**：加入绘本/小说/教材/科普四类分类与人工确认；完成结构化读书笔记草稿、编辑和主人审核；先使用本地演示用户，不开放公共社区。
- **共享与扩展阶段（P2）**：指定用户/限时链接分享、撤销、访问记录；增加历史、诗歌、漫画、工具书分析器；为章节讲解和知识点视频增加模板。

两周计划中新增的通用阅读任务属于 P1/P2 预研和接口骨架，不能挤占竞赛 P0 的真实视频和互动验收。如果算力、模型或时间不足，保留分类契约、笔记 schema、权限规则和可运行的本地原型，明确标记未完成，不把模拟分享当作正式上线。

## 9. 风险、依赖与待确认

1. **算力最大风险**：统一 GPU 的型号、显存、使用时长未知；图生视频的多页耗时可能远超 5 分钟展示。第 1 周实测并保留替换 provider；展示视频与现场生成过程分开说明。官方 HunyuanVideo-1.5 的最低 14 GB 条件使用 offload，可能速度不足。
2. **准确性风险**：ASR 错字、角色跨页变化、生成视频与原书不一致、点击位置漂移。分别用转写修正、角色表、视频帧证据、黑边坐标校验及低置信拒答解决。
3. **外部服务风险**：如赛事样本不得上传第三方或接口不稳定，就必须本地运行；不可在未经确认时发送授权绘本、音频或隐私内容。
4. **合规风险**：仅用组委会授权/脱敏材料；不公开传播完整衍生作品；模型权重/工具/音频/图片来源和许可证逐一登记；生成结果标年龄适配，人工复核儿童内容；赛后按通知删除受限数据。
5. **待官方确认**：延迟数值与计时定义、评测协议和 schema、隐藏新书、触控判分、视频格式、闭源 API 可用范围、现场限时任务细节。官网/规则与用户提炼稿若有差异，以正式规则为准。
6. **提炼稿待核对处**：原文称“7 项评分维度”但表内为 6 行；称“11 项指标”但括号列举 10 项；称“8 项合规自检”但列出 7 条。正式说明书须查官方原件，不自行补造。
