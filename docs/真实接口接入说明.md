# A/C 真实接口接入说明

v0.2 · 当前业务流程全部模拟，用户确认先完成前端。真实服务可用后再接入，不自动混用模拟成功结果。

## 接入位置

| 文件/层 | 作用 | 替换方式 |
|---|---|---|
| `src/api/client.ts` | 既有契约的 HTTP 适配器 | `createApiClient(baseUrl)`；错误和超时保持显式失败 |
| `src/app/WorkspaceApp.tsx` | 当前本地模拟编排 | 替换 `completeImport`、`generate`、`question`、`touch`、笔记与分享回调 |
| `src/app/types.ts` | 页面所需数据与回调 | 在服务层映射服务端字段，页面不解析任意原始响应 |
| `src/pages/SettingsPage.tsx` | 手动健康检查 | 只请求用户输入地址的 `/health`，不切换业务模式 |
| `src/pages/InteractiveReaderPage.tsx` | 展示视频/字幕/回答 | `book.video_url`、`run_id`、`origin=real` 只在真实响应后设置 |

`client.ts` 已预留仓库 v0.2 的建书、上传、解析、校对、发起运行、job/run 查询、音频问答、点击和历史接口；仅健康检查已连到设置页面。业务端点尚未接线。上传 multipart 名称暂按 `image`、`page_no`，音频按 `audio`、`video_ms`；必须和 A/C 的实际 OpenAPI 核对。

当前文本提问是模拟能力，既有正式契约要求音频问答。C 应提供录音组件、音频格式、转写修正策略和响应适配。D 的页面已提供转写文本和状态容器，不能把本地示例按钮当作真实录音。

## 必须对齐的字段

1. `progress` 单位、所有 job stage/status、错误码和 retryable。
2. `ocr_text` 与 Pydantic 的实际校对结构、revision、409 冲突。
3. 视频资产 URL、访问有效期、片段页码、时间轴、内容复核状态。
4. 问答 transcript/answer/audio_url/evidence/uncertain/latency_ms；延迟计时定义。
5. 点击坐标基于视频内容区，黑边扣除由前端展示组件执行；C/A 再做服务端校验。
6. 分类类型与低置信策略、主人权限、审核版本与分享版本。
7. 新增笔记/分享端点见 `frontend-contract-draft.md`，均待 A/C 定稿，不是已存在服务。

## 联调检查

建书失败、单页上传失败与重试、部分成功、取消、刷新恢复、超时、worker 重启、409、视频不可播放、无证据问答、黑边点击、未审核分享、越权、撤销、过期和修改已审核内容。连接真实数据后把模拟标记替换为服务端数据来源，保留 run_id 和失败记录。

## 验证边界

HTTP 适配器已使用拦截 fetch 的本地单元验证，见 `api-adapter-test.json`；没有连接真实服务。npm 安装、完整类型检查和正式生产构建被环境审批服务 403 拦截，需要联网环境补跑，不能由本地 TSX 转译代替。
