# A/C 真实接口接入说明

2026-11-05 · 以已同步的 A 后端 `backend/app/main.py`、`schemas.py` 为准。

## 已接入的页面

“接口与演示设置” → “A 后端实际接口联调”（`BackendWorkbench.tsx`）实际执行建书、原图上传、查询页面、规则分类、主人类型确认、人工校对、分析任务与进度/错误查询、最多三次尝试。该入口与主导航中的模拟数据分开；主流程仍持续显示演示模式，不会上传示例或把失败回退成模拟成功。

前端使用 Vite `/backend-api` 代理到本机 `127.0.0.1:8000`，避免修改 A 的 CORS。开发和 preview 有同一配置，离线 HTML 明确拒绝真实联调。

## 实际请求与返回

| 项目 | 当前实现 |
|---|---|
| 认证 | 私有接口 `Authorization: Bearer <token>`；缺令牌本地拒绝；401 原样展示。令牌只在组件内存中，离页清空 |
| 建书 | `POST /api/books`，返回 `id`，不再假定 `book_id` |
| 页图 | `POST /api/books/{id}/pages?page_no=N`，原始 Blob 字节，Content-Type 为 PNG/JPEG，不使用 multipart |
| 分类 | `POST .../classify` 与 `PATCH .../classification`；类型使用 `picture_book/novel/textbook/science/other`，不直接套用模拟 UI 的 fiction/nonfiction |
| 校对 | `PATCH .../pages/{page_no}/revision`，`{ocr:{text}}`；读取服务端 revision 和 manual_review 来源，没有虚构并发版本校验 |
| 分析 | `POST .../analyze`，`{analysis_profile}`；读取 job/run/progress/jobs，保留错误码；没有 progress 百分比则不编造 |
| 重试 | `POST /api/jobs/{id}/retry`；服务端最多三次尝试，超限 409 |
| 错误 | FastAPI `detail` 字符串/422 数组、非 JSON、网络错误、超时分别处理；不回显验证对象 input 或令牌 |
| 媒体 | `/assets` 与带认证的 `/assets/{id}/content` 下载 Blob；不能把私有地址直接放 video src 并期待自动附加 Bearer |
| 笔记/分享 | 适配器按 A 实际 content/action/share_mode 等字段实现；主流程尚未替换为真实服务，等真实分析结果后完成 |

删除了 A 不存在的 `/parse`、`/questions`、`/touches` 等推测请求。A 的 `interactions` 是 C 结果记录/检索接口，不能当成录音/点击模型推理。C 实际服务契约仍需对齐。

## 明确限制

A 尚未配置 B 的分析 provider，分析会真实失败为 `PROVIDER_NOT_CONFIGURED`；这是已验证的失败链路，不是完整 AI 功能。分类是标题规则原型。当前人工 OCR 校对由用户填写，没有自动 OCR。真实模型视频、语音问答、点击推理、主流程笔记与分享全链路、真机验收仍待后续。

上传途中失败后保留已创建 book.id，继续按钮先查询服务端已有页，只上传未完成页。刷新/离页不持久化凭据和联调状态；不自动删除服务端已创建对象。创建请求超时须先查询服务端状态，不能无条件当作未创建。
