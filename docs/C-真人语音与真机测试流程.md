# 真人语音与真机测试流程（约 15 分钟）

**目的**：补上队长审查指出的"真实语音和正式评测缺证据"。这些只能由真人完成：无头浏览器只能用虚拟麦克风，测不出真实识别效果和真机延迟。
**产出**：一份导出的 CSV、一份打分结果 JSON、一张人工判定表。三样一起交给 E 和队长。

> 边界：示例书是团队原创的 3 页合成内容，结果只能说明"真人说话 → 识别 → 检索"这条链路在真机上能用、效果如何，**不代表真实绘本的准确率**。真实绘本到位后按同样流程再测一次。

## 1. 准备

1. 按 `backend/README.md` 启动 A 的后端，记下自己的令牌。
2. 前端：`cd frontend && npm run dev`，用 **Chrome 或 Edge** 打开（浏览器语音识别需要它们）。
3. 右上角切到 **Live**，在「接口与演示设置」里填后端地址和令牌。
4. 记录测试环境：设备型号、系统、浏览器版本、麦克风（内置/耳机）、环境是否安静、说话人编号（不要写真名，例如 S1、S2）。

## 2. 建一本可提问的书（约 3 分钟）

导入页 →「试用原创示例」→ 勾选授权声明 → 确认导入 → 逐页校对确认 → 分类确认并开始分析。
分析会如实失败（后端没有接分析服务），这是正常的。然后点 **「先用校对文字做书页问答」** 进入阅读页，页面上应能看到 `run_id`。

## 3. 提问（每位说话人约 5 分钟）

按 `scripts/fixtures/voice-reference-sample-book.json` 的顺序，**用麦克风**逐条提问 V-01 ~ V-10：

- 每条：点录音 → 正常语速说完 → 停止 → 看识别出的文字；**识别错了就照实改正再提交**（系统会记下"改过字"，这也是证据）；
- 漏说或说错一条：重新说一遍即可，但导出后要把多余那条从 CSV 里删掉（打分脚本按顺序对齐，条数不一致会报错）；
- 每条回答出来后点「🔊 语音播报」，听一下有没有声音，在下表"朗读"一栏记有/无；
- 另外在视频或书页上点 5 次（主角、背景、黑边各至少一次），只看有没有被拦截/留痕。

## 4. 导出与打分

历史页 →「导出后端留痕与延迟统计」，得到 `interactions-<run_id>-<时间>.csv`，然后：

```bash
node scripts/score-voice-run.cjs ~/Downloads/interactions-xxx.csv scripts/fixtures/voice-reference-sample-book.json > voice-score-S1.json
```

输出包含：识别字错率 `cer`、改字比例 `edited_ratio`、识别失败条数、问答延迟 P50/P95，以及逐条对照。
**脚本不判断回答对不对**，回答正确与否请填下表。

## 5. 人工判定表（每位说话人一张）

| 编号 | 期望（见参考文件 expect） | 系统回答摘要 | 判定：对 / 错 / 应拒答且拒答了 / 应拒答却答了 | 朗读有声音 | 备注 |
|---|---|---|---|---|---|
| V-01 | 第1页：一封信 | | | | |
| … | | | | | |

**正确率** = （"对" + "应拒答且拒答了"）÷ 10。如实填写，答错的也要保留。

## 6. 交付

把 `voice-score-*.json`、导出的 CSV、判定表和测试环境记录一起发到群里或交给 E。
**不要上传录音文件**；CSV 里只有音频指纹，没有声音本身。
