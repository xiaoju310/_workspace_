# 本机数据与发布边界

## 仅保存在本机、不提交 GitHub

- 用户绘本文件、页图、校对文字、已有视觉分析、分镜与生成媒体。
- SQLite/MongoDB 数据、用户资料、密码散列、会话、阅读记录、问答与笔记。
- API 密钥、账户配置、运行日志、私人备份、截图、录屏、验收报告。
- Ollama 运行文件、本机模型权重和本机模型配置。

`data/` 保持原本的本机路径，更新源码不迁移或删除它，避免破坏已有运行记录。
MongoDB 和本机用户配置不进入仓库。参考/验收文件在本机保留，不再列入更新分支。
不要从运行中的数据库制作公开测试夹具；单元测试应使用临时目录和虚构内容。

## 发布操作

只暂存明确审核的软件文件；运行 scripts/check-publication.py 检查暂存区及最终提交树。
源码中仅允许明确登记的原创 UI 位图和自产 PDF 格式测试夹具；后者只有测试文字，无绘本内容。
不上传模型、安装包、整目录压缩包或含运行数据的 GitHub Release 附件。
本规则用于 GitHub 代码发布，不表示所有软件功能都离线；主动确认的云端功能有独立的数据发送边界。

## 历史限制

忽略规则、取消跟踪和新提交都不会删除旧提交里的内容。
本次不强推、不改写团队历史，也不声称旧分支、PR、缓存、派生仓库或已下载副本已清除。
如旧材料含受限内容，需另行确认范围后协调历史清理、权限调整和凭据轮换。
