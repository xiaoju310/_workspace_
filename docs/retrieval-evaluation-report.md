# 纸书智伴 · 二元组抽取式问答检索小评测报告

## 1. 评测背景与目标
在第一阶段整改中，系统彻底清除了“小狐狸”假数据兜底，改为基于字符二元组（Character Bigram）与区分度过滤的本地抽取式检索器（`TimeSliceIndexer` + `PictureBookRagEngine`）。
本评测旨在验证该方案在无外部深度学习模型时，对短问句、英文、数字、时序意图、多二元组长问句及域外问题的真实表现，评估 `MIN_COVERAGE = 0.4` 的合理性与已知缺陷。

## 4. 抽取式算法瓶颈剖析与参数探讨

### 4.1 `MIN_COVERAGE = 0.4` 的利与弊
- **有利面**：有效拦截了泛化噪声与口语短句，保证了只要回答就 100% 有依据（Precision = 100%）。
- **缺陷**：
  1. **长问句关键词稀释**：当儿童问出复杂句或带有修饰词的句子（如“如果从悬崖跳下去会怎样”），切出 `[如果, 悬崖, 崖跳, 跳下, 下去]` 共 5 个二元组。即使核心实体“悬崖”精准存在，命中率也仅有 `1/5 = 0.2`，低于 0.4，导致拒答。
  2. **纯时序意图补偿失效**：代码中设计了 `wantsEnding` / `wantsBeginning` 补偿 `coverage += 0.3`。但若问句中其他词在文本中均无重叠，基础 coverage = 0，加上 0.3 后仍为 0.3，无法越过 0.4 门槛。

### 4.2 单字符与独立数字的丢失
- 当前分词为了防止“的一是不了”等单字噪声，设置了 `if (run.length === 1) continue;`。
- 后果：儿童常问的单个字（如“鸟”、“花”、“狗”、“1”）由于长度为 1，直接被丢弃，导致二元组为空，100% 拒答。

### 4.3 跨语言与同义词
- 纯二元组基于字面完全匹配，英文无法匹配中文概念，同义词（如“大鸟” vs 原文“大雁”）无法对齐。这必须依赖真实 Embedding 或 LLM/VLM 模型。

---

## 5. 改进方向与演进路线
1. **短期规则优化**：
   - 当检测到时序意图（`wantsBeginning` / `wantsEnding`）时，若无其他实体冲突，可直接赋予保底有效性；
   - 对单汉字，可引入高频儿童名词白名单（动物、植物等），或者在无其他二元组时允许单字匹配；
2. **长期模型接入**：
   - 接入真实后端模型服务（B/A 端视觉与文本大模型），将二元组作为离线降级方案，彻底解决语义对齐与同义词理解。
