## 4. 常用测试（从项目根目录执行）

先按 `backend/requirements.txt` 和前端锁文件安装依赖；不要将依赖目录提交。
下面命令直接使用已安装的本地项目环境。

```powershell
# 后端 + AI 工具的普通回归；排除需要真实本地模型的 integration 测试。
# 含 MongoDB 账号测试，因此本机 MongoDB 服务必须运行。
$env:PYTHONPATH = Join-Path (Get-Location) 'backend'
$env:SERVE_FRONTEND = '0'
& .\backend\.venv\Scripts\python.exe -m pytest -q backend/tests tests -m 'not integration'

# 前端单元测试、类型检查和正式构建。
npm --prefix frontend-wonderland test
npm --prefix frontend-wonderland run build

# 建好前端后，使用随机本机端口和临时 SQLite 做前后端真实 HTTP 联调。
& .\backend\.venv\Scripts\python.exe .\scripts\check-wonderland.py
```

- `scripts/test-backend.ps1` 是仅后端测试的快捷入口，不包含根目录 `tests/` 的 AI 工具测试。
- `backend/tests/test_auth_mongo.py` 使用 `paper_companion_test_<随机编号>` 临时库，结束时仅删除该临时库；不使用正式账号库。
- 普通回归不请求付费模型。`integration` 标记的本地 OCR 测试需单独准备模型与依赖，不在本轮执行。
- `check-wonderland.py` 使用独立临时数据和测试身份，结束后停止测试服务，日志留在被忽略的 `test-results/`。
- HTTP 联调中，分析流程验证如实失败；笔记阶段由测试人工置成功。它不证明真实 AI 生成成功，也不代替第二台设备验收。
- `docs/verification/` 的离线截图和旧报告主要供历史参考，当前回归优先采用上面入口。
